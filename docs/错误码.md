# 错误码

统一错误结构：

```json
{
  "schema_version": "1.0",
  "request_id": "req_example",
  "error": {
    "code": "MODEL_NOT_FOUND",
    "message": "模型不存在",
    "details": {}
  }
}
```

初始分类保留 `AUTH_*`、`PERMISSION_*`、`DATASET_*`、`ANNOTATION_*`、`TRAINING_*`、`MODEL_*`、`CONTRACT_*`、`OBJECT_*` 和 `INTERNAL_*` 命名空间。具体错误码必须在对应 API/事件发布前登记，未知异常映射为已登记服务端错误码并保留 `request_id`，不得返回数据库异常、路径、密钥或堆栈。

多领域增量登记：

| 错误码 | 含义 |
| --- | --- |
| `ANNOTATION_SCHEMA_NOT_FOUND` | 请求的领域标注模式尚未发布 |
| `ANNOTATION_PAYLOAD_INVALID` | 标注内容不符合已发布模式 |
| `MODEL_ARTIFACT_INCOMPLETE` | 多制品模型缺少清单中声明的文件 |
| `MODEL_ARTIFACT_DIGEST_MISMATCH` | 模型制品文件摘要不匹配 |
| `MODEL_EVALUATION_EVIDENCE_REQUIRED` | 缺少固定评估集的不可变评估证据 |
| `DOMAIN_MODEL_NOT_QUALIFIED` | 领域模型尚未通过目标环境资格门禁 |
